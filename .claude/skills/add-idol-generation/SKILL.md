# Add Idol Generation

## Overview

Onboards a new XP idol generation into `server/data/db.json` plus the matching
generation-badge tag color in the frontend. The user supplies only: generation
number, member names (often in simplified-Chinese-typed characters), and a tag
color. Everything else — ids, per-single selection history, election-rank
placeholders, and creative persona fields — is generated here.

**Mechanical fields are generated by `generate_members.py`, not by hand.**
Hand-writing `selectionHistory` (one entry per single, currently 50+) or
`electionRanks` invites typos that corrupt the data shape. Use the script.

## Workflow

1. **Normalize names to standard Japanese kanji.** Users often type names with
   simplified-Chinese glyphs. Convert each to the real Japanese (shinjitai)
   form before anything else — e.g. `広` not `广`, `塚` not `冢`, `瀬` not `濑`,
   `沢` not `泽`. Don't guess at a name's reading if it's ambiguous — pick the
   most common/plausible one and generate ALL-CAPS `"GIVEN SURNAME"` romaji
   matching the existing pattern (`grep -n '"romaji"' src/App.jsx` isn't
   needed — check a few entries in `server/data/db.json` for the format).

2. **Read the DB for context** (one pass, e.g. with a short Python/jq
   snippet):
   - all `singles[].id` (selectionHistory keys)
   - all `singles[].tracks[].title` (the ONLY valid `favoriteSongs` pool —
     never invent a song title)
   - all `electionRanks[].edition` values across members (election editions)
   - all member ids + `isActive` flags (see step 4)
   - the previous generation's birthdays, to offset the new generation's
     average age if the user specifies a relative age (e.g. "about half a
     year younger")

3. **Give each member a distinct, vivid persona.** Same generation, no two
   alike: vary height, blood type, birthday, origin prefecture, and — most
   importantly — the *archetype* (genki/sporty, mysterious/artsy,
   dreamy/intellectual, tough/cool, motherly/reliable, etc.). Each of
   `hobby` / `skill` / `catchphrase` should read as one specific character's
   voice, not a generic idol-profile template. Reuse the tone of existing
   entries in `db.json` (short vivid sentence, not corporate copy) but never
   reuse an existing member's persona.
   - `favoriteSongs`: exactly 3 **real** track titles pulled verbatim from
     `singles[].tracks[].title`, thematically fitting the persona.
     `favoriteSong` = `favoriteSongs[0]`.
   - `favoritePokemon`: random int 1–151 (National Dex Gen 1 only — the
     frontend's `POKEMON_LIST` in `src/App.jsx` only has names for 1–151;
     anything higher silently renders as Bulbasaur's name with the correct
     sprite, a known display bug — stay in range instead of trying to work
     around it).
   - `admireSenior` (1–3 ids): any member, active or graduated — pull from
     the full member list.
   - `friends` (1–3 ids): **only from members with `isActive: true`.**

4. **Write a spec JSON** (see `generate_members.py` docstring for the exact
   shape) and run:
   ```
   python3 .claude/skills/add-idol-generation/generate_members.py spec.json
   ```
   This inserts the new members at the front of `members[]`, fills
   `selectionHistory` (every single → `"加入前"`) and `electionRanks` (every
   edition → `"加入前"`), sets `group: "XP"`, and leaves `avatar` /
   `officialPhotos` empty pending real photos. It validates `favoriteSongs`
   against real track titles and `admireSenior`/`friends` against real
   (and, for friends, active) member ids before writing anything — fix the
   spec and rerun if it errors.

5. **Wire up the tag color.** In `src/App.jsx`, add one line to
   `GENERATION_THEME` (around line 540):
   ```js
   "12": { backgroundColor: "#fb9398", color: "#FFFFFF", borderColor: "#fb9398" },
   ```
   Key is the bare generation number (string). Every generation
   badge/filter-pill/tag in the app reads this one table, so nothing else
   needs to change in the frontend. Also append a row to the **Generation
   Badge Colors** table in `CLAUDE.md`.

6. **Validate** — `python3 -c "import json; json.load(open('server/data/db.json'))"`
   should succeed with no errors.

## Quick Reference

| Field | Source |
|---|---|
| `id` | `m_<N>gen_<i>` (script) |
| `selectionHistory` | every `singles[].id` → `"加入前"` (script) |
| `electionRanks` | every existing edition → `"加入前"` (script) |
| `favoriteSongs` | 3 real titles from `singles[].tracks[].title` (you pick, script validates) |
| `favoritePokemon` | random 1–151 (you pick, script validates range) |
| `admireSenior` | 1–3 ids, any member (you pick, script validates existence) |
| `friends` | 1–3 ids, active members only (you pick, script validates) |
| generation tag color | `GENERATION_THEME["<N>"]` in `src/App.jsx` + `CLAUDE.md` table |

## Common Mistakes

- Inventing a `favoriteSongs` title instead of copying one verbatim from
  `db.json` — the script will reject it, but check first to avoid churn.
- Picking `friends` from a graduated member (`isActive: false`) — only
  `admireSenior` may include graduated/senior members.
- Giving every member in the batch the same archetype/tone — defeats the
  "鲜明人设" requirement; vary hobby/skill/catchphrase voice per member.
- Setting `favoritePokemon` above 151 — displays with the wrong name in the
  UI even though the sprite icon is correct (see step 3).
- Hand-editing `selectionHistory`/`electionRanks` instead of using the
  script — easy to miss a single or mistype `"加入前"`.
